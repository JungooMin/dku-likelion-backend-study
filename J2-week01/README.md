# Week 01

이번 주차에는 Java를 이용하여 간단한 할 일 관리 서비스를 구현해보았습니다.  
사용자로부터 명령어를 입력받아 할 일을 추가, 조회, 수정, 삭제하는 기능을 구현하면서 CRUD의 기본 개념을 학습하였습니다.

또한 하나의 클래스에 작성되어 있던 기능을 메서드와 Controller 클래스로 분리하면서 각 클래스가 역할을 나누어 처리하도록 코드를 구성해보았습니다.

---

## CRUD

CRUD는 데이터를 다룰 때 사용하는 기본적인 네 가지 기능을 의미합니다.

- Create : 데이터 생성
- Read : 데이터 조회
- Update : 데이터 수정
- Delete : 데이터 삭제

이번 할 일 관리 서비스에서는 다음과 같이 구현하였습니다.

| 기능 | 명령어 |
| --- | --- |
| 할 일 추가 | `add` |
| 할 일 목록 조회 | `list` |
| 할 일 수정 | `modify` |
| 할 일 삭제 | `del` |
| 프로그램 종료 | `exit` |

---

## Scanner를 이용한 사용자 입력

`Scanner` 객체를 사용하여 키보드로부터 사용자의 명령어와 할 일 내용을 입력받았습니다.

~~~java
Scanner scanner = new Scanner(System.in);
~~~

`System.in`은 표준 입력 스트림으로, 콘솔에서는 키보드로 입력한 데이터를 받아올 수 있습니다.

`scanner.nextLine()`을 사용하면 사용자가 Enter를 입력할 때까지 입력을 기다리고, 입력된 문자열을 가져올 수 있습니다.

프로그램이 계속해서 명령어를 입력받을 수 있도록 `while (true)`를 사용하고, `exit` 명령이 입력되면 반복문을 종료하도록 구현하였습니다.

## Todo 객체

프로그래밍에서는 서로 연관된 데이터를 하나로 묶어서 관리하는 것이 좋다는 점을 학습하였습니다.

할 일 관리 서비스에서는 각 할 일의 번호와 내용을 따로 관리하지 않고 `Todo` 클래스를 만들어 하나의 객체로 관리하였습니다.

Todo 객체는 다음과 같은 정보를 가집니다.

- `id` : 할 일 번호
- `content` : 할 일 내용

새로운 할 일을 추가할 때마다 Todo 객체를 생성하고 해당 객체에 번호와 내용을 저장하도록 구현하였습니다.

---

## List를 이용한 Todo 관리

사용자가 몇 개의 할 일을 생성할지 미리 알 수 없기 때문에 배열보다 `List<Todo>`를 사용하여 Todo 객체들을 관리하였습니다.

배열은 크기가 정해져 있지만 List는 필요한 만큼 데이터를 추가할 수 있기 때문에 할 일과 같이 개수가 계속 변할 수 있는 데이터를 관리하기에 적합합니다.

새로운 Todo 객체가 생성되면 `add()`를 이용하여 List에 저장하였습니다.

또한 저장된 할 일을 출력할 때는 반복문을 이용하여 List에 들어있는 Todo 객체들을 하나씩 확인하였습니다.

~~~java
for (Todo todo : todos) {
    ...
}
~~~

향상된 for문을 사용하면 List에 저장된 할 일의 개수만큼 반복하면서 각 Todo 객체에 접근할 수 있습니다.

## 할 일 삭제와 수정

### 할 일 삭제

`del` 명령을 입력하면 삭제할 할 일의 번호를 입력받고, `removeIf()`를 이용하여 해당 Todo 객체를 삭제하도록 구현하였습니다.

~~~java
todos.removeIf(todo -> todo.getId() == id);
~~~

`removeIf()`는 List의 각 요소에 조건식을 적용하고, 조건식의 결과가 `true`인 요소를 제거합니다.

### 할 일 수정

`modify` 명령에서는 입력받은 번호에 해당하는 Todo 객체를 먼저 찾은 뒤 내용을 수정하였습니다.

~~~java
todos.stream()
        .filter(todo -> todo.getId() == id)
        .findFirst()
        .orElse(null);
~~~

`filter()`를 이용하여 조건에 맞는 Todo를 찾고 `findFirst()`를 통해 가장 먼저 찾은 객체를 가져옵니다.

조건에 맞는 객체가 존재하지 않는 경우에는 `orElse(null)`을 통해 `null`을 반환하도록 하였습니다.

## 메서드 분리

처음에는 `App`의 `run()` 메서드에서 대부분의 기능을 처리하였지만 기능이 추가될수록 메서드의 크기가 커졌습니다.

실습을 진행하면서 클래스와 메서드는 가능한 한 하나의 역할을 담당하도록 작게 나누는 것이 유지보수에 좋다는 것을 학습하였습니다.

반복문이나 메서드의 흐름을 제어할 때 사용하는 명령어의 차이도 학습하였습니다.

- `break` : 현재 반복문 종료
- `continue` : 현재 반복을 건너뛰고 다음 반복 진행
- `return` : 현재 메서드 종료

## Controller를 이용한 역할 분리

최종적으로 `TodoController`와 `SystemController`를 만들어 기능을 분리하였습니다.

각 클래스의 역할은 다음과 같습니다.

- `Main` : 프로그램 실행
- `App` : 사용자의 명령을 입력받고 적절한 Controller로 전달
- `Todo` : 할 일의 번호와 내용을 저장
- `TodoController` : 할 일 추가, 조회, 수정, 삭제 처리
- `SystemController` : 프로그램 종료 처리

Controller는 사용자와 직접적으로 소통하면서 요청을 처리하는 역할을 합니다.

기존에는 `App`에서 여러 기능을 직접 처리했지만, 기능을 분리한 이후에는 각 Controller가 자신의 분야와 관련된 요청을 처리하고 `App`은 입력된 명령에 따라 적절한 Controller로 요청을 전달하도록 구성하였습니다.

이를 통해 하나의 클래스에 여러 기능이 몰려있는 것보다 각 클래스의 역할을 구분하는 것이 코드를 이해하고 유지보수하기에 더 좋다는 것을 알 수 있었습니다.

## 느낀 점

이번 실습을 통해 Scanner, 객체, List, 반복문 등 이전에 배운 Java 문법들이 실제 프로그램을 구현할 때 어떻게 함께 사용되는지 확인할 수 있었습니다.

특히 처음에는 하나의 `App` 클래스에서 대부분의 기능을 구현했지만, 기능이 많아지면서 메서드를 분리하고 이후에는 Controller 클래스까지 분리하는 과정을 통해 클래스와 메서드의 역할을 나누는 이유를 이해할 수 있었습니다.

또한 `removeIf()`와 `stream().filter()`를 직접 사용하면서 List에 저장된 데이터 중 원하는 데이터를 찾고 수정하거나 삭제하는 방법도 익힐 수 있었습니다.
